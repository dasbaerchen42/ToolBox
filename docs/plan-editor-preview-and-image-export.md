# 編輯器：MD/HTML 渲染切換 + 文轉圖

## 需求

1. 編輯器要吃得下 Markdown 與 HTML，可以在純文字與渲染之間切換。
2. 文轉圖：把整篇內容（含渲染結果）下載成 PNG，寬度由工具自己決定，跟視窗大小無關。

## 決策

| 題目 | 決定 |
| --- | --- |
| 切換型態 | 三態：純文字／渲染／並排（並排只在 `md` 以上出現） |
| 渲染綁在哪 | 綁既有的 `WritingMode`，不另開模式。只有 `markdown` 與 `html` 有渲染 |
| 渲染管線 | `marked` → `DOMPurify`。HTML 模式跳過 marked 直接清洗 |
| MD 裡混寫 HTML | 天然支援：marked 會原樣吐出，最後一起被 sanitize |
| 截圖寬度 | 600 / 800 / 1080 CSS px，一律 2 倍輸出（1080 → 2160 px） |
| 長圖超過上限 | 自動分頁，多張時用既有的 `jszip` 打包成 zip |
| 匯出配色 | 跟著當下主題的 CSS 變數走，深色主題就是深底淺字 |
| 含標題 | 預設**關閉**（內文開頭常常已經有一個 `#` 標題，會重複） |
| 「裁切」怎麼做 | 做在**內容層**（挑段落），不做像素層拖框——拖框一定會切到半行字 |
| 挑張數 | 產生後出縮圖列，勾要下載的；單張 PNG、多張 zip |
| 分頁方式 | 自動（依區塊高度打包）／手動（自己點在哪裡切）／一律單張 |
| 貼上 | 整頁 ⌘V／Ctrl+V 為主，剪貼簿按鈕為輔（手機用）；一律開新文件 |
| 貼上帶格式時 | 問使用者要保留格式（HTML 模式）還是純文字 |

## 實作要點

- `lib/markdown.ts`：`marked` 與 `dompurify` 都用動態 `import()` 載入，不進首屏 bundle；
  sanitize 只開 `html` profile，不開 SVG / MathML。
- `lib/export-image.ts`：**不截畫面上那塊預覽**。預覽寬度會跟著視窗跑，手機永遠截不出
  1080 寬的圖，所以另外在畫面外（`left: -100000px`）組一個固定寬度的節點來截。
  - 分頁門檻取 iOS Safari 的 canvas 面積上限（約 16.7M 裝置像素）保守估算，
    1080 寬 2 倍輸出時一頁約 3700 CSS px。
  - 換頁點盡量落在區塊元素之間，避免把一行字從中間切斷；單一元素本身超過一頁才硬切。
  - 截圖前 `await document.fonts.ready`，否則字型會掉回系統字。
  - 截圖庫用 `html2canvas-pro`：原版 `html2canvas` 遇到 `oklch()` 會直接丟錯，
    而 Tailwind v4 的預設調色盤就是 oklch。
- `app/globals.css` 的 `.md-preview`：Tailwind preflight 會清掉標題與清單樣式，這裡補回來。
  顏色一律走主題變數，螢幕上與匯出的 PNG 才是同一套配色。

## 匯出視窗（第二階段）

「轉圖」改成開一個視窗：挑段落 → 產生 → 挑張數 → 下載。

- 段落選取：把渲染後的 HTML 用 `splitBlocks()` 拆成頂層區塊，每塊前面一個勾選框，
  支援 Shift 點第二下選一整段範圍。匯出時只把選取的區塊接起來餵給截圖引擎，
  所以邊界永遠落在區塊之間。
- 一律單張放不下時丟 `ExportTooLongError`，訊息帶上實際高度與上限，
  而不是丟一張空白圖給使用者（iOS Safari 的典型症狀）。

## 手動分頁（第三階段）

- 分頁的最小單位就是一個頂層區塊，所以換頁點永遠落在區塊之間，不會從一行字中間切開。
- 手動模式：點一下段落 = 在它後面切一刀（再點一次取消），勾選框仍然只管選不選
  （`stopPropagation`）。上方即時顯示「目前切成 N 張」。
- 切得不夠細時，產生會擋下並指名「第 N 張約 X px」，而不是硬切或吐空白圖。
- 每一張是把不屬於這張的區塊 `display: none` 之後整塊截圖，**不是把長圖裁開**，
  所以每張的高度就是它自己內容的高度，邊界永遠是完整的區塊。
- 自動分頁也一起換成照區塊高度依序打包（原本是先算像素範圍再硬切）。
- 畫面上的分頁點記的是「第幾個區塊」，匯出的內容只有選取的區塊（且含標題時標題排最前），
  所以送進 `exportContentToImages` 前要換算位置；取消選取某個區塊時，它的分頁點一併移除。

## 貼上流程

- `hooks/usePagePaste.ts`：監聽整頁的 paste 事件，游標在 input/textarea/contenteditable
  裡時完全不介入（不能干擾正常打字貼上）。走 paste 事件所以**不需要剪貼簿權限**。
- `lib/clipboard.ts`：`readClipboard()` 給手機用（沒有 ⌘V），優先用 `clipboard.read()`
  取 text/html，失敗退回 `readText()`，再失敗就提示改用鍵盤。
- 貼上一律**開新文件**，不覆蓋正在寫的東西，所以純文字可以完全免確認。
  純文字給 markdown 模式（段落、清單直接就能渲染），保留格式給 html 模式。
- 只有真的帶排版標籤才問要不要保留格式；剪貼簿附的那種「純文字包在 div 裡」不問。

## 已驗證

Playwright 實機走查：三態切換、Markdown 渲染（標題／清單／表格／引言／程式碼區塊）、
Markdown 內混寫 HTML 有渲染、`<script>` 與 `onerror` 被清掉、
純文字模式轉圖、Markdown 轉圖（2160 px 寬）、長文自動分成 9 張並打包 zip，無 JS 錯誤。

第二階段：整頁貼上純文字（免確認、自動開新文件、標題取第一行）、帶格式貼上會跳詢問且
選「保留格式」後進 HTML 模式、剪貼簿按鈕、段落勾選（10 段全選／取消兩段／全選）、
一律單張遇到長文給出「內容約 31600 px，超過單張上限 3573 px」的提示、
自動分頁產生 9 張後只勾第 2 與第 4 張 → zip 裡確實只有 `-02.png` 與 `-04.png`。

第三階段：112 段的長文切 10 刀 → 顯示「切成 11 張」、10 個 ✂ 標記、實際產生並打包 11 張；
只切 2 刀時被擋下並提示「第 3 張約 4793 px，超過單張上限 3573 px」；
點勾選框不會順便切一刀；自動與一律單張兩種模式行為不變（9 張／擋下）。
